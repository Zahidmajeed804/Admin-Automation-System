# Team Overtime and Team Leave

Reviewers (`overtime.approve`, `leave.approve`/`leave.reject`) now get a **Team**
tab on the Overtime and Leave pages, alongside the existing **Pending approvals**
tab — the same "filter everyone, approve/reject inline" shape as Team Attendance.
A new lightweight `GET /users/options` endpoint feeds the employee filter on
both, open to any reviewer (not just `users.manage`).

Run on 2026-09-28 over real HTTP and in real headless Chrome against the live
MongoDB, using a temporary manager and a temporary staff account with a real
overtime request (generated by actually clocking in/out against a lowered
threshold) and a real leave request. **All 17 Chrome checks and every API
check passed.** All test accounts, roles, and the attendance/overtime/leave
records they generated were deleted afterwards; the backend was restarted at
the normal 10-hour threshold.

## How to repeat it yourself

Takes about 8 minutes (includes a real ~4-minute wait for worked time to pass
a lowered test threshold) with the backend and frontend already running
against a live `MONGO_URI`.

### 1. Set up a manager and a staff member with real requests

1. As an admin, create two staff logins from **Attendance → Staff**
   (see [`AAS-383-388-staff-management.md`](AAS-383-388-staff-management.md)).
   Give one the **manager** role via the roles/permissions tool.
2. Restart the backend with a short overtime threshold so you don't have to
   wait 10 hours:
   ```bash
   OVERTIME_THRESHOLD_MINUTES=3 npm run dev
   ```
3. Log in as the staff member, clock in, wait about 4 minutes, clock out —
   this creates a pending overtime request. Submit a leave request from the
   **Leave** page too.

### 2. Review from the Team tab

| # | Do this | You should see |
|---|---|---|
| 1 | Log in as the manager, open **Overtime** | **Pending approvals** and **Team** tabs |
| 2 | Click **Team** | the same filter row as Team Attendance: Employee, Status, From, To |
| 3 | Filter Employee to the test staff member | the table narrows to just their request |
| 4 | Click **Approve**, confirm | the row updates to **Approved** without leaving the page |
| 5 | Open **Leave**, click **Team** | Employee, Type, Status, From, To filters |
| 6 | Filter Type to their leave type | narrows correctly |
| 7 | Click **Reject** on their row, confirm | the row updates to **Rejected** |

### 3. Confirm the permission boundary

| # | Do this | You should see |
|---|---|---|
| 8 | Log in as the staff member (no approve permissions), open dev tools, call `GET /users/options` | 403, not the employee list |

## Clean up

```bash
cd backend
URI=$(grep '^MONGO_URI=' .env | cut -d= -f2-)
mongosh "$URI" --quiet --eval '
const ids = db.users.find({ email: /^qa39[0-9]\..*@example\.com$/ }).toArray().map(u => u._id);
print("overtime:", db.overtimerequests.deleteMany({ user: { $in: ids } }).deletedCount);
print("leave:", db.leaverequests.deleteMany({ user: { $in: ids } }).deletedCount);
print("attendance:", db.attendances.deleteMany({ user: { $in: ids } }).deletedCount);
print("userroles:", db.userroles.deleteMany({ user: { $in: ids } }).deletedCount);
print("users:", db.users.deleteMany({ _id: { $in: ids } }).deletedCount);
'
```

Then stop the backend and start it normally (`npm run dev`, no
`OVERTIME_THRESHOLD_MINUTES` override) so the threshold goes back to 10 hours.

## If something does not match

| You see | Likely cause |
|---|---|
| No **Team** tab on Overtime/Leave | the account lacks `overtime.approve` (Overtime) or both `leave.approve`/`leave.reject` (Leave) |
| Employee filter is empty or fails to load | `GET /users/options` needs `overtime.approve` **or** `leave.approve` — a manager without either gets a "Couldn't load employees" hint, same pattern as Team Attendance |
| Approving/rejecting from Team doesn't update the row | check the dialog didn't show a 409 — someone else may have already decided it; the table re-fetches either way |
| No overtime request appears after clocking out | the backend needs `OVERTIME_THRESHOLD_MINUTES` set low enough, and worked time must actually exceed it |
